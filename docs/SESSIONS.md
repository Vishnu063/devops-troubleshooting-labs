# Timed practice and hidden incidents

Sessions are optional. Existing `show`, `up`, `check`, and `record` commands still work without timers or level gates.

`--blind` and `--hidden` mean the same thing. Fresh native `up` and `reset` automatically confirm an expected live failure before declaring readiness. They poll for up to about 120 seconds by default; individual runtime commands have their own timeouts. Use `session up --wait 240` for a slower environment (maximum 300). A timeout reports **NOT READY**, and runtime/API errors are setup errors, not proof of the intended fault. Resources remain available for diagnosis and scoped cleanup.

An existing Git/Docker workspace is preserved by `up`, including repairs. To prove its starting failure for the current attempt, use `python3 lab.py session verify-fault`; to recreate the fault, use `python3 lab.py session reset`. Do not reset a repair you want to keep. Starting-fault timestamps live in ignored `.lab-state/ID/startup.json`. A previous attempt's timestamp does not establish readiness for a new session.

## Start a hidden incident

```bash
python3 lab.py session start --hidden --runnable --level 1
python3 lab.py session up
python3 lab.py session status
python3 lab.py session check
```

The starting brief shows symptoms, runtime, and time remaining. It omits the case title and catalog ID. Setup prints the actual namespace or workspace needed for diagnosis. Local resource names and readable source files can reveal IDs or faults; hidden mode is an honor-system practice aid, not an anti-cheating sandbox.

The timer starts when the session starts, including setup. Pre-pull images before starting a timed attempt, or choose a longer budget with `--minutes 45`. No background notification or auto-deletion runs when time expires. `status` displays remaining time; the session remains usable after expiry, but no longer counts toward level unlocking.

## Evidence, hints, and finish

```bash
python3 lab.py session evidence
python3 lab.py session hint --step 1
python3 lab.py session finish --score 8
python3 lab.py progress
```

Native sessions are rechecked at finish. A previous pass is not trusted after later changes. Scores assess your explanation using the rubric; they are not generated by AI or the grader. Evidence drills have no automated repair check and remain self-assessed.

`python3 lab.py session hint` automatically opens the next unopened hint; explicit `--step 1`, `2`, or `3` still works. Standard-case hint 3 contains the diagnosis and therefore marks the solution as revealed, even if it is the only hint you opened. Compound hint 3 remains an investigation prompt. Hidden successful setup suppresses subprocess chatter as well as Python setup messages; resource paths still identify the environment you must investigate.

Opening `session solution` marks the session as revealed. A qualifying completion requires:

- A self-assessed score of at least 7/10.
- Finishing within the selected time budget.
- At most one distinct hint opened.
- No solution revealed through the session command.
- Successful current recovery checks for native labs.
- A starting fault confirmed during the current attempt for native labs.

A finish records elapsed seconds, hints, timeout, reveal status, and whether native recovery was verified. Lab resources remain available for inspection; the finish output prints the cleanup command. `session abandon` ends the timer without creating a completion and also prints cleanup instructions.

## Optional level unlocking

```bash
python3 lab.py session path
python3 lab.py session start --level 2 --unlock --hidden
```

Level 1 is always open. Level 2 requires qualifying completions on three distinct Level 1 cases; Level 3 requires three distinct Level 2 cases. Repeating one case does not unlock the next level. Manual `record` entries do not unlock levels. Omit `--unlock` to practice freely at any level.

These gates help structure study. They do not certify production competence, and local JSON history is editable.

## Multiple independent faults

```bash
python3 lab.py session start --compound --hidden
python3 lab.py session up
python3 lab.py session check
```

The three compound incidents are additional to the final 100. Repair one fault, collect fresh evidence, and keep investigating until end-to-end recovery passes. Their default target is 60 minutes.

## Reset or clean up during a session

```bash
python3 lab.py session reset
python3 lab.py session down
```

Reset restores the original broken state and clears the remembered verification flag. It keeps the original timer, hints, and reveal status. Starting a new session requires finishing or abandoning the current one; it cannot silently replace an active attempt.

History is stored in ignored `.practice/` files. Back up that folder yourself if you want to keep it across machines. Sessions support one active attempt per checkout; do not run concurrent history-writing commands.
